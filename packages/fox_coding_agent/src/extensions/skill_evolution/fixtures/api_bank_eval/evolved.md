# API 请求规划

读取对话与接口说明，确定当前尚未完成的用户意图，只选择题目提供的一个 API。

## 依赖检查
- 生成请求前，先检查目标 API 是否依赖认证令牌等前置结果。
- 若依赖未满足，应调用获取依赖的 API，而不是直接调用目标 API。
- 若对话中已有可复用的令牌或结果，应直接使用，不要重复请求认证。
- 若任务有依赖，只输出当前依赖已满足的下一次调用，不要声称调用已经成功。

## 参数规范
- 参数名必须来自接口 schema，优先使用 schema 中的字段名。
- 参数值必须严格来自对话或已有调用结果，不得留空或编造。
- 若对话未提供所需值，应请求用户补充。
- 注意区分相似参数名，如设备名与设备 ID、用户名与邮箱。
- 列表或对象类型参数按 schema 要求构造结构，不要转成字符串。
- 数值型参数按语义单位填写，如每间房人数而非总人数。
- 文本参数保留对话中的原始表述，不要自行改写或截断。

## 输出格式
最终严格按题目指定的 `API-Request: [ApiName(key='value')]` 单行格式回答。
